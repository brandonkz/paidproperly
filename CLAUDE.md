# PaidProperly: instructions for Claude

paidproperly.co.za is a directory of remote work platforms that pay South Africans, plus calculators and blog guides.
Owner: Brandon Katz. Marketing is run by the Agentic CMO system (Supabase project `agentic-cmo`, client slug `paidproperly`).

## How the site works
- Plain HTML, CSS and JavaScript. No build step, no framework.
- Hosted on GitHub Pages (CNAME paidproperly.co.za). A push to `main` goes live in about a minute.
- Blog posts live in `/blog/*.html`. The list is `blog/index.html`. Styles: `style.css` + `blog/blog-style.css`.
- `/content/` holds markdown drafts and `content/pipeline.md` (publish log). `/content/` is noindexed.
- `sitemap.xml` at the root must list every public page.
- Platform pages: `/platforms/*.html`, data in `/data/`. Affiliate redirects: `/go/` (generated by `generate-redirects.js`).

## Voice
- Casual, direct, South African. "Sorted for Mzansi". Short sentences. Local terms are fine (howzit, lekker).
- Talk in rands as well as dollars. South African context first: SARS, two-pot, Payoneer/Wise, load shedding.

## Rules
- Never promise earnings. Pay figures must match the platform page or a cited source.
- Tax content is general information, not tax advice. Say so on tax-heavy posts.
- Affiliate links go through `/go/<platform>`; keep the disclosure page linked.
- Do not delete or rename existing blog URLs. Update in place instead.
- Do not touch `ads.txt`, `CNAME` or the AdSense script.

## Publishing a blog post (Agentic CMO flow)
1. Read approved posts from Supabase:
   `select id, title, body, meta from content where client_id = (select id from clients where slug='paidproperly') and channel='blog' and status='approved' and (scheduled_for is null or scheduled_for <= now()) order by scheduled_for nulls first;`
2. For each row write a JSON file outside the repo with:
   `slug, title, body_md (= body), meta_title, meta_description, target_keyword, keywords, related, cta` (from `meta`).
3. Run `node scripts/publish-post.js <file.json> --push`. It writes `blog/<slug>.html`, adds the card to `blog/index.html`, updates `sitemap.xml` and `content/pipeline.md`, commits and pushes.
4. On `"ok":true`, update the row: `status='published', published_url=<url>, external_id=<commit>`. On failure set `status='failed'` and put the error in `feedback`.
5. Log each run in `agent_runs` (agent `blog-publisher`).

Body rules for `body_md`: no H1 (the title is the H1). Use `##` sections, short paragraphs, lists, simple tables, `[text](url)` links. The first paragraph becomes the intro.
